# Emulate

GB / GBC / GBA / NDS를 하나로 묶은 안드로이드 에뮬레이터 앱입니다.

| 기종 | 코어 |
| --- | --- |
| Game Boy / Color / Advance | [mGBA](https://github.com/libretro/mgba) (libretro) |
| Nintendo DS | [melonDS DS](https://github.com/JesseTG/melonds-ds) 1.4.0 (libretro) — BIOS/펌웨어 없이 동작(실기 BIOS를 넣으면 그것을 사용) |

앱은 두 코어를 `dlopen`으로 불러 쓰는 자체 libretro 프론트엔드(`app/src/main/cpp`)와 Kotlin UI로 구성됩니다.

## 디자인

Material 3(Material You)을 따릅니다. Android 12 이상에서는 배경화면 색으로 앱 색이 정해지고, 시스템의 밝은/어두운 테마를 따릅니다(게임 화면은 항상 어둡게). 글꼴은 [Google Sans Flex](https://github.com/googlefonts/googlesans-flex)(SIL OFL 1.1, `app/src/main/assets/licenses/GoogleSansFlex-OFL.txt`)이며, 한글은 기기 글꼴로 표시됩니다. 아이콘은 Material Icons(Apache 2.0)입니다.

## 기능

- ROM 라이브러리: 기기에서 ROM을 가져오면 앱 저장소로 복사합니다. NDS는 배너의 아이콘과 제목을 보여 줍니다.
- **정보 · 이름 바꾸기**: 게임을 길게 눌러 ROM 정보(헤더의 내부 제목, 게임 코드, 지역, 제조사, 카트리지 종류, 헤더 체크섬, CRC32, 세이브·상태 저장 현황)를 보고, 목록에 보일 이름(별칭)을 정할 수 있습니다. 파일 이름은 그대로라 세이브와 상태 저장에 영향이 없습니다.
- 터치 게임패드: 멀티터치를 지원하고, A·B 사이를 손가락으로 미끄러지듯 옮겨 누를 수 있으며, 진동 피드백이 있습니다. NDS 하단 화면은 직접 터치합니다.
- **터치 버튼 배치 편집**: 게임 메뉴의 **터치 버튼 배치 편집…**에서 방향키·A/B(XY)·L·R·SELECT·START·MIC·메뉴·빨리 감기 버튼을 끌어서 옮기고, 크기를 바꾸고(50~200%), 숨길 수 있습니다. 배치는 GB/GBC·GBA·NDS와 세로/가로 화면마다 따로 저장됩니다(`TouchLayout.kt`). 설정에서 모두 초기화할 수 있습니다.
- 블루투스/USB 게임패드와 키보드
- 배터리 세이브 자동 저장(`files/saves/<rom>.sav`, GB RTC는 `.rtc`), 세이브 스테이트(슬롯 8개, 저장할 때의 화면을 미리보기로 보여 줌, 길게 눌러 삭제. 슬롯 1은 빠른 저장/불러오기 단축키용)
- **세이브 관리**: 게임을 길게 눌러 세이브를 가져오거나 내보낼 수 있습니다(실기 추출 .sav, 다른 에뮬레이터의 .sav/.srm, DeSmuME .dsv 자동 변환). 오른쪽 위 ⋮ 메뉴에서 전체 백업(ZIP)과 복원을 할 수 있습니다.
- ROM은 .zip으로 묶인 채로도 추가할 수 있습니다.
- NDS 화면 배치: 세로/가로 화면마다 따로 설정됩니다(가로 기본값은 좌/우). 위·아래 바꾸기, 한쪽 크게 보기도 됩니다.
- NDS 마이크와 덮개: 터치 컨트롤의 **MIC** 버튼을 누르고 있으면 게임에 "부는 소리"가 들어갑니다(촛불 끄기, 바람 불기 등). 덮개는 게임 메뉴에서 닫거나 열 수 있습니다.
- 치트: 게임 메뉴의 **치트…**에서 코드를 추가하고 켜거나 끌 수 있습니다. GB/GBC는 GameShark와 Game Genie, GBA는 GameShark·Action Replay·CodeBreaker, NDS는 Action Replay 코드를 씁니다. 코드는 게임마다 `files/cheats/<rom>.json`에 저장됩니다.
- 설정: 버튼 불투명도·크기, 누를 때 진동, 럼블 진동, 소리, 게임보이 화면 색상(기본값은 GBC처럼 자동 색칠).
- **화면 출력**: OpenGL ES로 그립니다(필터: 선명하게 / 원본 픽셀 / 부드럽게 / LCD 격자). GPU를 못 쓰면 CPU 확대로 대신합니다. 게임 프레임 수(약 59.7)에 맞게 디스플레이 주사율 전환을 요청하고(Android 11+), 60/120Hz 화면에서는 주사율에 맞춰 프레임을 내보내 끊김 없이 움직입니다. 설정에서 **성능 정보 표시**를 켜면 게임/화면 fps와 코어 처리 시간이 보입니다.
- **주변 빛 번짐(앰비언트)**: 게임 화면 가장자리 색이 화면 위아래(가로 화면에서는 양옆) 배경으로 은은하게 번지고, 게임 화면이 바뀌면 함께 바뀝니다(GPU에서 그림, 설정에서 끌 수 있음). 세로 화면에서는 게임 화면이 컨트롤러 위 공간의 가운데에 오고, 컨트롤러는 필요한 높이만 씁니다. 화면이 짧은 폰(16:9 등)에서 NDS처럼 세로로 긴 화면은 DraStic처럼 가로를 꽉 채우고 버튼을 아래 화면 위에 올리며, 👁 버튼으로 다른 버튼을 모두 숨기거나 다시 보이게 할 수 있습니다(가로 화면에서 버튼이 게임 위에 겹칠 때도 같음).
- **게임 속도**: ▶▶ 버튼으로 빨리 감기(×1.5~×8, 누를 때마다 켜고 끄기 또는 누르고 있는 동안만), 게임 메뉴의 **게임 속도…**에서 ×0.5·×0.75 느리게도 고를 수 있습니다. 빨리 감기·느리게 모두 소리가 원래 음높이 그대로 나옵니다(시간 늘이기·줄이기, WSOLA). 빨리 감기 중 소리는 설정에서 끌 수 있습니다.
- **NDS BIOS·펌웨어(선택)**: 설정에서 직접 추출한 bios7.bin·bios9.bin·firmware.bin을 넣으면 내장 대체 BIOS 대신 사용합니다(셋 다 있어야 함).
- **NDS 무선 통신**과 **GB/GBC/GBA 통신 케이블**: 같은 Wi-Fi에 있는 폰끼리 연결합니다(아래 참고).
- **GBA 슬롯(Slot-2)**: NDS 게임을 길게 누르면 GBA 게임을 꽂을 수 있습니다. 이때 GBA 게임의 세이브 파일을 그대로 함께 쓰므로, 팔파크처럼 GBA 세이브에서 데이터를 옮기는 기능이 GBA 쪽 세이브에도 반영됩니다.

## NDS 무선 통신 (로컬 무선)

같은 Wi-Fi(또는 한쪽 폰의 핫스팟)에 연결된 기기끼리 DS 근거리 무선 통신(포켓몬 교환·대전, 유니온룸 등)을 할 수 있습니다.

1. 두 기기 모두 이 앱에서 게임을 실행합니다.
2. 한 기기에서 메뉴 → 무선 통신 → **방 만들기**를 누릅니다.
3. 다른 기기에서 **방 찾기**(또는 **IP로 참가**)로 참가합니다.
4. 연결되면 게임 안에서 평소처럼 통신을 시작합니다.

- melonDS DS의 넷패킷 인터페이스를 앱이 UDP로 중계합니다(`app/src/main/cpp/netplay.cpp`, 포트 47000). 구조는 방장을 중심으로 한 스타형이며, 최대 16대까지 연결됩니다.
- 기기마다 고유한 DS MAC 주소를 한 번 만들어 계속 사용합니다. 내장 펌웨어의 MAC은 모든 기기에서 같기 때문입니다.
- 통신 중에는 빨리 감기와 상태 불러오기를 막습니다. 상대 기기와 동기화가 깨지는 것을 막기 위해서입니다.
- 지연에 민감하므로 같은 공유기나 핫스팟 안에서만 동작합니다. 인터넷 너머로는 동작하지 않습니다. 공용 Wi-Fi는 기기 간 통신을 막는 경우가 많습니다.
- `python tools/netplay_peer.py`는 실제 DS를 흉내 내지 않고 통신 규약만 따르는 테스트용 가짜 상대입니다(방 찾기, 참가, 호스트 역할).

## GB / GBC / GBA 통신 케이블

메뉴의 **통신 케이블…**에서 NDS 무선 통신과 같은 방식(방 만들기 / 방 찾기)으로 연결합니다. GB와 GBC 게임끼리는 서로 연결되며(최대 2명), GBA 멀티플레이 케이블은 최대 4명까지 연결됩니다. GBA는 방을 만든 기기가 1P(부모)입니다.

mGBA libretro 코어에는 네트워크 링크 기능이 없어서 직접 추가했습니다(`cores/mgba-link/`, `patches/mgba-link.patch`; `scripts/build-cores.sh`가 적용합니다). GB 시리얼, GBA 멀티플레이 모드, GBA 노멀 모드(8/32비트)를 libretro 넷패킷으로 에뮬레이션합니다.

- 전송을 시작한 쪽은 상대의 응답이 올 때까지 기다립니다. 이 동안 에뮬레이션 시간은 멈춰 있으므로, 게임 입장에서는 전송이 즉시 끝난 것처럼 보입니다.
- 응답하는 쪽은 시작 측이 직전 전송 이후 진행한 사이클 수(gap)만큼 자기 에뮬레이션을 진행한 시점에 정확히 응답합니다. 그래서 다음 바이트를 준비할 시간이 실제 하드웨어와 같습니다.
- 통신이 활발한 동안에는 서로 2프레임 이상 앞서가지 않도록 맞추고, 네트워크를 약 0.25ms 간격(에뮬레이션 시간 기준)으로 확인합니다.
- 전송 한 번마다 네트워크 왕복이 한 번 필요합니다. 그래서 전송이 잦은 구간(예: 3세대 포켓몬 통신)은 Wi-Fi 지연에 비례해 느려집니다. 통신 중에는 Wi-Fi 저지연 모드를 켭니다.

### 링크 테스트 도구

- `tools/make_test_roms.py`가 만드는 `linktest.gba`(멀티플레이)와 `linktest_master.gb` / `linktest_slave.gb`(시리얼)는 상대가 이전 전송을 제때 처리했는지 매 전송마다 검사합니다. 정상이면 화면이 초록, 오류가 나면 빨강입니다.
- `tools/linktest/linktest.c`는 PC(Windows)에서 코어 여러 개를 띄우고, 지연과 지터를 넣은 메모리 네트워크로 연결해 테스트하는 하네스입니다.
- `tools/linktest/linkpeer.c`는 PC의 코어가 앱이 만든 방에 UDP로 참가하는 종단 간 테스트 도구입니다.

```bash
gcc -O2 -o linktest.exe tools/linktest/linktest.c -lpthread
./linktest.exe mgba_libretro.dll linktest.gba 4 10 2 1
```

## 빌드

```bash
scripts/fetch-cores.sh      # 고정된 커밋의 코어 소스를 third_party/에 받습니다
scripts/build-cores.sh      # NDK로 코어를 빌드해 app/src/main/jniLibs/에 넣습니다 (arm64-v8a, x86_64)
./gradlew assembleDebug
```

필요한 것: Android SDK, NDK 28.2, CMake 3.22.1, JDK 17 이상(Android Studio 내장 JBR이면 됩니다).

## 테스트용 ROM

`python tools/make_test_roms.py out/` 명령은 버튼 입력에 따라 화면 색이 바뀌는 아주 작은 GBA/NDS ROM을 만듭니다. 상용 게임 없이 화면 출력, 입력, 세이브 스테이트, Slot-2를 확인하는 용도입니다.

## 라이선스

melonDS DS가 GPLv3이므로, 이 코어를 포함해 배포하는 앱 전체도 GPLv3을 따라야 합니다. mGBA는 MPL 2.0입니다.
ROM은 직접 소유한 카트리지에서 추출한 것만 사용하세요.

## 화면 출력과 프레임 페이싱

`app/src/main/cpp/video.cpp`

- 에뮬레이션 스레드는 완성된 프레임을 3중 버퍼에 복사만 합니다. 그리는 일은 별도 스레드가 OpenGL ES 2로 하므로 확대·필터 비용은 GPU가 맡고, 에뮬레이션이 화면 출력 때문에 멈추는 일이 없습니다.
- vsync 스레드는 AChoreographer로 화면 갱신 시각을 받아 **주사율 시계**를 만듭니다. 마지막 vsync 시각과 측정한 주기로 다음 갱신 시각을 예측하므로, 콜백이 늦게 와도 시계는 느려지지 않습니다.
- 주사율이 게임 속도의 정수배와 1% 이내로 맞으면(60Hz, 120Hz) 한 프레임을 n번의 갱신마다 정확히 하나씩 돌립니다. 이때 남는 0.5% 정도의 속도 차이는 소리 재생 속도로 맞춥니다. 맞지 않으면(90Hz, 144Hz 등) 시계 기준으로 돌립니다. 통신 중에도 시계 기준입니다.
- **빨리 감기를 끈 뒤 끊김을 막는 처리**:
  - 속도가 바뀌면 프레임 일정을 "지금"부터 다시 잡습니다. 밀린 프레임을 한꺼번에 따라잡는 일은 없습니다.
  - 꺼 두었던 소리를 다시 켤 때는 버퍼를 목표 지연만큼 무음으로 채운 뒤 시작합니다. 빈 버퍼에서 시작하면 소리가 수 초 동안 지직거릴 수 있기 때문입니다.
  - 빨리 감기 중에는 화면이 보여 줄 수 있는 프레임만 넘깁니다.
  - Android 13+에서는 Performance Hint API로 프레임당 목표 시간과 실제 처리 시간을 시스템에 알려, CPU 클럭이 실제 부하에 맞춰 오르내리게 합니다.
